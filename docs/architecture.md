# 设计与维护约束

本客户端围绕一个边界构建：目标机器只运行它原本就有的 Claude Code TUI，所有操作经过本地 shell 或 SSH。禁止添加 SDK/API 代理、OAuth 文件读取、远程 HTTP/WebSocket 服务或隐藏的模型请求。

## 数据流

1. 用户配置主机和目录。配置序列化时只接受白名单字段，原子写入本地 `workspaces.json`。
2. 后端解析目标目录，批量检查项目 JSONL 的文件标识、字节数及时间戳。首次或检测到变化时读取头尾元数据并核对 cwd，后续目录刷新复用未变化文件的元数据。
3. 新建会话预分配 UUID，执行 `claude --session-id`；续接执行 `--resume`。UUID 写入 pane 用户选项，不写入 Claude 原始文件。
4. 选中会话启动一个串行读取循环。旧选中会话的异步结果通过 watch 对象身份丢弃。错误保留当前消息并逐步退避，连接恢复后继续字节游标。
5. 一次往返同时读取 JSONL 增量和进程状态。原生状态稳定且没有增量时短暂复用上一帧，保留原抓屏时间。用户查看终端、正在生成或画面发生变化时按需更新。历史未加载完时不将当前屏幕合并到较早的一轮。
6. TranscriptStore 根据 UUID、父记录、rewind 和 compact 标记恢复当前消息分支。MessageDisplay 在这个分支上聚合同一轮的文本和工具，用稳定 turn ID 供 React 原位更新。上下文用量从同一分支的已完成请求读取。JSONL 有优先权，屏幕仅补充可确定匹配的临时尾部。
7. 本机诊断记录每一步的关联 ID、时序、字节计数、哈希和错误堆栈。原文记录按用户授权默认开启，屏幕变化和 JSONL 读取片段写入受限滚动日志；不写回目标 JSONL，不上传。离线重放通过 poll.apply 记录重建相同输入顺序并校验消息及状态摘要，不能将缺失或被截断的日志宣称为完整复现。
8. 目录树按目录缓存发现结果，展开只加载子列表，选择会话才切换唯一的消息 watch。每目录请求合并、全局最多两个发现请求并行；编辑、删除和新建通过版本号丢弃陈旧结果。后台失败保留已读历史并标为未确认。
9. 当前 viewport 和滚屏分别读取：原生状态文件和当前 viewport 提供运行状态，滚屏用于消息预览。终端默认只读。用户接管时输入由绑定当前 pane 的令牌控制，交还后作废原生设置缓存。

默认启动保留目标的配置环境，不强制设置 `CLAUDE_CONFIG_DIR`。该变量不仅决定历史目录，还会改变 Claude 全局配置的位置；只有用户明确设置自定义目录时才覆盖。历史查找与实际启动使用相同解析规则。

处理原生设置时，每次操作只读取一次目标的 `keybindings.json`。发送操作键前复核文件标识以识别中途修改。模型及 effort 选项来自当前 TUI 菜单，绑定不明确或原生 hook 要求确认时可在终端交给用户处理。

每次由 Lectern 启动新的原版进程（包括从历史 `--resume`），启动器通过内联 `--settings` 传入此进程专用的 `statusLine.command`。该命令利用目标上已有的 tmux 将回调交给对应 pane。客户端在正常的会话轮询中取得数据，按当前前台进程、启动标记和会话 UUID 核对归属。只要该进程仍在运行，退出后重开 Lectern 也能再次读到同一 pane 的最新回调。其他终端、用户及项目的 Claude 配置保持原来的行为。

界面采用回调中的模型、原生报告的 effort、窗口容量及可用的输入用量和百分比。缺少使用记录时保留已知容量。由 Lectern 启动的新进程只在用户进入选择器时枚举菜单，票据留在当前 App 进程内。没有 Lectern 状态栏回调的 pane（如显式绑定的 pane）可从原生菜单初始化，并按已验证的进程身份复用本机 `session-settings/` 缓存。普通会话按用户原有状态栏运行。[Claude Code 状态栏字段](https://code.claude.com/docs/en/statusline#available-data)

同一前台进程的两个选择器分别缓存完整的原生菜单五分钟。再次展开有效菜单时，renderer 直接显示当前快照中的选项。主动刷新或有效期届满后，已有选项可供查看，读取成功后才可选择。主进程再次核对票据，后端在应用变更前核对原生选项和当前选择。进程更替、终端接管及设置变更会使相关菜单失效，切换模型也使其对应的 effort 菜单失效。

首次读取将 pane 身份和抓屏放进同一条目标命令，发送菜单按键时一并采样后续画面。发送 Enter 前，Lectern 确认原生输入框内是刚才输入的完整命令。若轮询恰好留下菜单的等待状态，关闭后立即读取新画面，确认用户是否仍需处理提示。

输入 `/model` 或 `/effort` 时，Claude 的补全列表可能混入项目命令或技能。Lectern 按描述列对齐识别多行选项，同时核对输入框和候选焦点。用户主动重读同一个设置时，若终端已留下完整命令且对应的原生候选已聚焦，可直接继续。后台初始化仍要求空输入框。原生菜单挤走历史首行时，只剥离与进入菜单前的历史尾部逐行吻合的部分。

## 输入边界

renderer 不拥有 Node 权限。sandbox + contextIsolation，preload 只暴露白名单方法，主进程校验 IPC sender。没有任意文件读写、任意命令或任意 URL 打开接口。renderer 网络请求被拦截，Markdown HTML 不执行。

连接目标以参数数组传给 `ssh`，目标 shell 的参数统一单引号转义。消息通过 stdin 写入 tmux 专用 buffer，不插入 shell 命令。不允许终端控制字符。前台进程验证缩小 Claude 退出后向 shell 发文字的风险；外部 pane 仍存在检查与发送间的竞态，无法提供内核级原子保证。客户端创建的 pane 使用 exec，Claude 退出后不会落回交互 shell。

SSH 使用既有 known_hosts，禁止首次连接时默默接受指纹。连接复用只创建本地临时 ControlPath。远端不开监听端口，不传输任何安装脚本。

## 非稳定接口

Claude Code JSONL 和 TUI 不是公开稳定的 UI 协议。升级时优先运行 parser fixtures 与实际 tmux 测试，然后人工检查一个真实但低风险的会话。未知记录忽略，坏记录提示，原始文件不改。不能把模拟器通过解释成所有 Claude Code 版本兼容。

支持原生 PID 状态文件的版本会把会话身份、工作状态及 tmux 位置写入数字 PID 的 JSON 文件。Controller 结合进程树与启动标记确认归属，发现身份变化时撤销旧绑定的输入能力。缺少这些文件的旧版 Claude Code 仍使用用户显式建立的绑定。关闭操作先验证前台进程并请求其退出，然后只清理匹配的 pane，历史文件可继续读取。
